User guide

How the simplified flow works

1

Register

Enter project ownership, team, classification, and useful business context. The app generates a permanent PRJ-* ID.

2

Build in development

Use notebooks, jobs, pipelines, dashboards, Apps, SQL, or Git folders in {{ settings.dev_workspace_name }} and {{ settings.dev_catalog }}.

3

Tag assets

Selected assets need project_tag, environment, and data_classification. Default Bundle name prefixes are allowed.

4

Request production

Select assets and identify the Git branch and Bundle. A protected validator checks both Bundle targets and source tags. No SHA is requested; revisions are recorded only as audit evidence.

5

Approve and deploy

An approver reviews the request. Approval rechecks tags and queues a team-scoped production deployment job running as a protected service principal.

6

Verify

The production worker deploys, runs optional validation, reads all mandatory production tags back, and records terminal status and evidence.

Mandatory tag values

KeyDevelopmentProduction
project_tagThe registered project ID
environmentdevprod
data_classificationThe project’s registered classification
